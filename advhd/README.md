# WS2 文本工具

WillPlus / AdvHD 引擎 `.ws2` 脚本的文本提取与回封工具，为
《恋はそっと咲く花のように》（ensemble，2021）编写。

提取出译者可直接编辑的双行文本，翻译后回封为**加密脚本**，可直接放回游戏。
支持译文变长（日译中/日译英长度必然变化），并在每一步做逐字节校验。

---

## 快速开始

图形界面，把脚本文件夹拖进去，点两个按钮：

```console
python ws2_tool/run_gui.py
```

命令行（以下均在**游戏根目录**下执行，即 `ws2_tool` 的上一级）：

```console
# 1. 提取文本
python ws2_tool/disassembler.py 文本 -o 文本_text

# 2. 翻译 文本_text/texts/*.txt 里的 ● 行

# 3. 回封
python ws2_tool/assembler.py 文本 文本_text -o 文本_rebuilt

# 4. 把 文本_rebuilt/rebuilt/ 里的文件放回游戏
```

新版语料同理，只是把两处 `文本` 换成 `新版文本`：

```console
python ws2_tool/disassembler.py 新版文本 -o 新版文本_text
python ws2_tool/assembler.py 新版文本 新版文本_text -o 新版文本_rebuilt
```

回封前想先看看会改动什么，加 `--dry-run`：只做校验和预览，不写任何文件。

需要 Python 3.11+，只用标准库。GUI 的拖放依赖 `windnd` 或 `tkinterdnd2`，
缺失时自动降级为「浏览…」选择文件，不影响使用。

## 译文格式

每条三行：注释行给出编号与说话者，`○` 行是原文（**不要改**），`●` 行填译文。

```text
# idx=00000006 off=0x00000D4C tag=msg speaker=<@FIRNAME>
○00000006○msg○「本っ当に申し訳ございませんでした！！」
●00000006●msg●「真的非常抱歉！！」
```

几条规则：

- **只改 `●` 行。** `○` 行是校验锚，导入时逐字符比对，不一致就拒绝——这一条
  同时挡住错位、误改原文、用旧文件导入、以及编辑器的自动全角化和智能引号。
- **不要留空。** 导出时 `●` 行预填原文，「未翻译」的判据是它等于原文而不是
  为空。空行视为误删并报错。因此翻一半也能随时回封，未翻的部分显示原文。
- **`<@FIRNAME>` 这类 `<@XXX>` 必须原样保留。** 它是玩家名变量，由引擎运行时
  替换。删掉或写错不会被长度和编码检查发现，只会在游戏里显示不出名字，所以
  单独加了校验。
- 译文可以比原文长，不需要压字数。

引擎控制码（`%LC`、`%K%P`、`%XS20`、`%XE` 等）已经从正文里剥掉了，不出现在
译文文件里，回封时自动拼回。

## 输出目录

```text
文本_text/                       ← 提取产物
  texts/<原文件名>.ws2.txt       译者编辑的双行文本，与源一一对应
  asm/<原文件名>.ws2.asm.txt     可选，--asm 才生成（改逻辑用）
  _work/reports/                 覆盖证书、提取报告、形态报告
  _work/ir/                      可选，--with-ir 才生成（排查用）

文本_rebuilt/                    ← 回封产物
  rebuilt/<原文件名>.ws2         **加密脚本**，放回游戏用的就是这个
  rebuilt_plain/<原文件名>.ws2   明文副本，便于比对（--no-plain 可关）
  _work/reports/                 回封报告、策略裁决、重定位日志
```

默认输出目录与输入**同级**（不在输入目录内部），因此第二轮运行不会把上一轮
产物当成新输入。原始文件全程只读，回封产物一律进新目录，需要你自己复制回游戏。

无可翻译文本的系统脚本（图层擦除、初始化等）不产出译文文件，但**照常参与
回封**——游戏需要一套完整脚本，缺文件会出问题。

## 两个版本的语料

同一引擎的两批语料在**字符串编码**上不同，opcode 与操作数布局完全相同：

| 语料 | 文件数 | 字符串形态 | 提取条目 |
|---|---|---|---|
| `文本/` | 262 | CP932，单字节 NUL 终止 | 30,563 正文 / 18,216 人名 / 5 选项 |
| `新版文本/` | 9 | UTF-16LE，双字节 NUL 终止 | 1,618 正文 / 1,038 人名 |

形态是**按文件结构自动判定**的，不看文件名也不看目录：两种形态各跑一遍全量
解析，取唯一能让指令流严丝合缝覆盖整个文件的那个。两个方向都验证过——
新版用 UTF-16 全通过、用 CP932 有 45 个撞未定义 opcode；旧版反之。

UTF-16 语料的译文仍写 UTF-16LE（终止符是双字节，换单字节编码游戏读不出来），
好处是能表示任意字符，不存在「GBK 表示不了这个字」的问题。

## 编码

界面上两个下拉框，对应原文编码与译文编码。

- 原文编码留空即按形态自动判定（CP932 或 UTF-16LE）。
- 译文编码留空则取形态默认值：单字节形态用 GBK，UTF-16 形态用 UTF-16LE。
- 选错的典型后果是某些字写不进去。此时会明确报出**是哪个字**，例如
  「译文编码 gbk 无法表示「♪」」，而不是静默替换成 `?`。旧版语料里确实有一条
  含 `♪` 的台词，用 GBK 会被拦下，换 `gb18030` 即可。
- 双行文本文件本身固定 UTF-8 带 BOM，记事本打开不乱码。

## 变长回封

译文变长是本地化的常态，不是错误。超出原空间时会自动从「原地写回」切到
「引用回填」，重新计算所有跳转目标，界面上不需要你做任何事。

回封后会重新解析产物并校验：能否完整重新解析、覆盖率是否仍为 100%、
引用站点集合是否同构、**新译文是否真的出现在输出里**、未改动的条目是否逐字节
不变、总长度变化是否等于各条目变化之和。任一项不过就拒绝输出，失败样本留在
`_work/tmp/failed/` 供排查。

最后一项容易被忽略但很关键：「文件能解析」不能证明「译文写进去了」。

## 校验与已验证的性质

| 项目 | 旧版 262 个 | 新版 9 个 |
|---|---|---|
| 解析 + 零编辑往返逐字节一致 | 262/262 | 9/9 |
| 加密产物对照原始归档 | 262/262 == `Rio.arc` | 9/9 解密后 == 源 |
| 技能门禁（8 项） | 全过 | 全过 |
| 测试 | 55 项全过 | |

加密方向是对着 `Rio.arc` 里的原始字节验的，不是自洽往返——单靠往返一致发现
不了加解密方向写反（开发中确实写反过一次，正是这一步抓出来的）。

跑测试（在 `ws2_tool` 目录下）：

```console
cd ws2_tool
python -m pytest tests -q
```

## 文件

| 文件 | 职责 |
|---|---|
| `opcodelist.py` | 声明式方言：87 个 opcode、加解密、字符串形态、文本规则 |
| `disassembler.py` | 源二进制 → 内存 IR → 双行文本 / ASM / 覆盖证书 |
| `assembler.py` | 源 + 译文 → 重建并加密；也是回封的命令行入口 |
| `repack.py` | 批量编排，GUI 与命令行共用同一实现 |
| `run_gui.py` | 两按钮图形界面 |
| `vm_analysis.md` | 逆向分析与证据台账，上述各文件的唯一真值源 |
| `tests/test_ws2.py` | 55 项测试 |

引擎特定的数值只出现在 `opcodelist.py`，其余模块不含任何魔数——这一条由
门禁脚本机械检查。适配同引擎的其他作品只需改方言声明。

## 已知限制

- **只在这一部作品的两个版本上验证过。** 同引擎其他作品（script 版本
  1.06 / 1.4 / 2.11）没有样本，那些版本的操作数宽度是照参考实现声明的，
  除 1.9 之外均未实测。
- **不支持改指令和控制流。** 理解深度申报 T3（完整指令边界），没做基本块与
  可达性分析，因此改 ASM 里的指令会被明确拒绝并说明所需深度，而不是产出一个
  能加载但行为错乱的文件。改字符串没有此限制。
- `0x13` 的长度与参考实现（9 字节）不同，本版本实测为 0 字节。两个方向都验过：
  取 0 则 262/262 通过，取 9 则 37 个文件失败。详见 `vm_analysis.md` 的
  `EV_UNK13_ZERO_LENGTH`。
- 87 个 opcode 中有 32 个在本作未出现，其布局只有参考实现单一来源，未经本语料
  交叉验证。
