# Yu-Ris 游戏文件工具

两个独立的功能，界面上是两个标签页：

- **翻译脚本**：把脚本文件（`yst*.ybn`）里的台词导出成可编辑文本，翻译完再装回去。译文可以比原文长。
- **解包封包**：把资源归档（`*.ypf`）里的文件取出来，改完再打包回去。

一般顺序是：先用「解包封包」取出 `ysbin` 之类的目录，再用「翻译脚本」处理里面的脚本。
如果脚本文件已经在硬盘上（多数游戏是这样），直接用「翻译脚本」就行。

已验证的范围：

- **翻译脚本**：3 款游戏共 1,425 个脚本文件，全部通过「不改动时导出再装回，文件逐字节不变」
  的自检。涵盖 YSTB 版本 **300 和 553**：`77 ～And，two stars meet again～` 936 个
  （534 个原始日文 + 402 个已加密的中文补丁版本）、`Nepgear2` 395 个、
  `G.I.B.ガールズ・イン・ブラック` 94 个（v553）。
  版本 553 是逐项实测后才加进来的——头部布局、单元尺寸、加密方式、密钥恢复、argc 不变式
  与 v300 完全一致。不在已验证清单里的版本会直接报出版本号拒绝，不会猜着处理。
- **解包封包**：6 款游戏共 74 个 `.ypf`（约 16 万个文件），全部处理成功。涵盖归档版本
  290 / 292 / 500，以及 6 种不同的内部布局组合（路径密钥 `0xC0`/`0xC9`/`0xFF`、两种路径长度表、
  路径哈希 CRC32/Murmur2、数据哈希 Adler32/Murmur2/XXH32）。布局是逐个归档探测的，
  不靠版本号猜——同一个版本 500 在不同游戏里就有三种布局。

## 需要什么

Python 3.11 或更新版本，不需要装任何第三方库。

想用拖放功能的话可以额外装一个：`pip install windnd`。没装也能用，界面上会提示改用「浏览」按钮。

拖入的目标是**当前在前面的那个标签页**：在「翻译脚本」页拖入会填脚本文件夹，在「解包封包」页
拖入会填归档文件。正在处理任务时拖入会被忽略并提示，不会打断当前任务。

## 怎么跑

**图形界面**（推荐）：双击 `run_gui.py`，或者

```
python run_gui.py
```

窗口上方两个标签页对应两个功能，各自有自己的路径框，互不影响。

### 翻译脚本（命令行）

```
python disassembler.py "D:\Game\ysbin" -o "D:\Game\ysbin_text"
python assembler.py    "D:\Game\ysbin" --texts "D:\Game\ysbin_text" -o "D:\Game\ysbin_rebuilt"
```

加 `--dry-run` 只检查不写文件。加 `--asm` 一并导出 ASM 清单（改游戏逻辑才需要，翻译不用）。

### 解包封包（命令行）

```
python ypf_tool.py info    "D:\Game\pac\cg.ypf"
python ypf_tool.py extract "D:\Game\pac\cg.ypf" -o "D:\Game\cg_extract"
python ypf_tool.py extract "D:\Game\pac"        -o "D:\Game\all_extract"
python ypf_tool.py pack    "D:\Game\cg_extract" "D:\Game\cg_new.ypf" --metadata-dir "D:\Game\cg_extract"
```

`extract` 给文件夹时会把里面每个 `.ypf` 解到各自的子目录，不会互相覆盖。
`-e` 可以指定路径编码（默认 `cp932`）。

## 产出的文件

| 位置 | 是什么 |
|---|---|
| `texts/` | 双行文本，翻译就改这里，和原脚本一一对应 |
| `asm/` | 脚本结构清单，只有加了 `--asm` 才有，翻译不需要 |
| `rebuilt/` | 装回去之后的脚本文件 |
| `reports/` | 处理报告和校验记录，出问题时贴给开发者用 |

## 解包封包怎么用

在「解包封包」标签页里选一个 `.ypf` 文件，或者选装着一堆 `.ypf` 的文件夹（通常叫 `pac`）：

- **查看信息**：显示版本、文件数、编码方式。不确定某个归档能不能处理时先点这个。
- **解包**：把里面的文件取出来。选文件夹时每个归档解到各自的子目录。
- **封包**：把改过的文件夹重新打包成 `.ypf`。

解包时会在输出目录留一个 `.ypf_meta.json`，记录了每个文件原本的类型和压缩方式。
**封包时不要删它**，界面会自动用上；命令行需要用 `--metadata-dir` 指向解包目录。

**有些 `.ypf` 根本不是归档**，工具会认出来并说明：

- **视频文件**：片头动画常直接以 `op.ypf` 命名，内容其实就是视频本身。工具按文件内容判断格式
  （实测遇到过 MPEG 和 WebM 两种），解包时按真实格式另存，例如 `.webm` 而不是 `.mpg`。
- **空的更新槽**：游戏里未使用的 `update*.ypf` 可能只是个 16 字节占位文件。工具会标为「跳过」，
  这不是错误，也不影响其他归档。

**封包结果和原始归档不会逐字节相同**，因为压缩实现和当年的工具不同。但解包出来的文件内容一致，
游戏能正常读取。改动前请备份原始 `.ypf`。

## 双行文本怎么改

每一条是三行：一行注释、一行 `○` 原文、一行 `●` 译文。

```
# idx=00000024 off=0x0000137A inst=140 tag=msg
○00000024○msg○這一帯是知之塔的地盤，普通科的学生就只有我一个。
●00000024●msg●这一带是知之塔的地盘，普通科的学生只有我一个。
```

规则只有三条：

- **只改 `●` 行**，`○` 行是原文对照，改了会被拒绝。
- **`●` 行不能留空。** 刚导出时它和原文一样，表示「还没翻译」；留空表示内容被误删，会被拒绝。
- **不要动 `idx` 数字和 `tag`**，也不要删行、不要调整条目顺序。

### 人名单独一行

带说话者的台词会拆成两条：`tag=name` 是人名，`tag=msg` 是台词，注释里的 `pair=` 指向另一半。

```
# idx=00000019 off=0x00000683 inst=89 tag=name pair=00000020
○00000019○name○知枝
●00000019●name●知枝

# idx=00000020 off=0x00000683 inst=89 tag=msg pair=00000019
○00000020○msg○「等等等等，起立、鞠躬之前！\n　今天有事要决定的」
●00000020●msg●「等等等等，起立、鞠躬之前！\n　今天有事要决定的」
```

人名**不带**方括号，`【】` 是游戏语法，装回去时工具会自动加上，不要自己写。
两条可以各自单独翻译，改一条不影响另一条。

### 人名定义表

有些游戏（如 `Nepgear2`、`G.I.B.`）用单独一个脚本集中定义所有角色名，里面没有台词，
全是 `tag=name`。**每个角色占两行**，因为脚本里就是存了两处：

```
# idx=00000001 off=0x000000A3 inst=6 tag=name
○00000001○name○兔              ← 脚本用来认人的标识
●00000001●name●兔

# idx=00000002 off=0x000000B2 inst=6 tag=name
○00000002○name○兔              ← 实际显示出来的名字
●00000002●name●兔
```

两行内容常常一样，但**要各自改**，改一处不会自动同步另一处。行数只看脚本结构，
不看内容是否重复，所以条目编号稳定、不会因为改了名字而变化。

写成 `内部ID＠显示名` 的形式时两行内容就不同了：

```
○00000004○name○空＠？？？       ← 内部ID＠显示名
○00000005○name○？？？           ← 实际显示出来的名字
```

`＠` **前面的内部 ID 不要翻译**，脚本靠它认人，改了会导致对不上；要改显示名就改 `＠` 后面那半。

### `\n` 是换行

`\n` 表示这句话在游戏里换行显示。位置可以调整，数量也可以改（想多分一行就多加一个）。

唯一的例外：少数台词在脚本里是**分成几段存的**，这种改动数量会被拒绝并提示需要几段——
报错信息会说清楚。绝大多数台词不受此限。

### 其他

`{{41:42}}` 这样的大写方括号是没法正常显示的原始字节，照抄就行，不要删、不要改大小写。

有些条目注释里带 `frozen=1`，那是音效名之类的内部数据，导出只为了让你看见，改了会被拒绝。

## 改完怎么装回去

界面上点「回封文本」，会先给一个预览（改了多少条、长度变化多少），确认后才写文件。

写出来的文件在「回封输出」目录里，**你需要自己把这些 `.ybn` 文件复制回游戏的脚本目录**
（记得先备份原文件）。工具从不修改游戏原文件。

只翻译了一部分也可以随时装回去，没翻译的部分会照原样显示。

## 报错怎么办

### 译文文件的问题

| 报错 | 意思 | 怎么办 |
|---|---|---|
| `SOURCE_ANCHOR` | `○` 原文行和脚本对不上 | 别改 `○` 行。如果没改过，可能是用了旧的译文文件，重新导出一次 |
| `EMPTY_TRANSLATION` | `●` 行是空的 | 把原文抄回去；「不翻译」是让两行相同，不是留空 |
| `SRC_SHA256` | 这份译文是从别的版本脚本导出的 | 重新导出文本，把译文搬过去 |
| `ROW_DELETED` | 少了条目 | 不要删行，重新导出后重做 |
| `ROW_REORDERED` | 条目顺序被调换了 | 保持原顺序，不要移动整块 |
| `IDX_MISMATCH` | 三行的 `idx` 不一致 | 三处数字必须相同 |
| `IDX_WIDTH` | `idx` 不是 8 位数字 | 保持 `00000024` 这样的定宽格式 |
| `IDX_DUPLICATE` | 同一个 `idx` 出现两次 | 删掉多余的那块 |
| `IDX_UNKNOWN` | 这个 `idx` 在脚本里不存在 | 别手工加条目 |
| `TAG_MISMATCH` | `tag` 被改了 | 改回原来的值 |
| `BULLET_MIXED` | `○` 和 `●` 混用了 | 一行三个分隔符必须一样 |
| `ROW_MALFORMED` | 分隔符不是三个 | 检查是不是误删了 `○` 或 `●` |
| `ROW_ORPHAN` | 有文本行但上面没有注释行 | 不要删注释行 |
| `SOURCE_ROW_MISSING` | 只有 `●` 行没有 `○` 行 | 补回原文行，或重新导出 |
| `HEADER_MISSING` | 文件开头四行的说明不见了 | 不要删文件头 |
| `SHARD_INCOMPLETE` | 这是分片文件，缺其他片 | 把所有片凑齐再导入 |
| `FROZEN_EDITED` | 改了不可修改的条目 | 把 `frozen=1` 的条目改回原样 |
| `ENCODING_UNREPRESENTABLE` | 译文里有字写不进目标编码 | 报错会指出是哪个字；换一种译文编码，或换掉这个字 |
| `PLACEHOLDER_BROKEN` | `{{...}}` 写坏了 | 里面必须是大写十六进制，像 `{{41:42}}` |
| `PAIR_BROKEN` | 人名和台词是一对，另一半不见了 | 不要删条目；重新导出文本后重做这一条 |
| `PART_COUNT_MISMATCH` | 这条台词分段存储，`
` 数量必须和原文一致 | 报错会说明需要几段，补齐或删掉多余的 |
| `UNEDITABLE_ARGUMENT` | 这条的存储形式不支持修改 | 把它改回原样 |

### ASM 清单的问题（只有改了 `asm/` 才会遇到）

| 报错 | 意思 | 怎么办 |
|---|---|---|
| `ASM_STRUCTURE_CHANGED` | 改了指令或增删了行 | 这个游戏只支持改字符串，不支持改指令逻辑；把结构改回原样 |
| `ASM_SID_UNKNOWN` | `sid=` 指向不存在的位置 | 不要手工改 `sid` |

两个编辑面同时改了同一条且内容不同时，会列出冲突的 `idx` 和两边的值并停下，需要你决定保留哪个。

### 归档文件的问题

| 报错 | 意思 | 怎么办 |
|---|---|---|
| `Not a YPF archive or header is broken.` | 不是 `.ypf` 归档，或文件损坏 | 确认选对了文件 |
| `File is too small to contain a YPF header.` | 文件被截断（空更新槽不会报这个，会显示「跳过」） | 重新获取原文件 |
| `Invalid YPF header table length.` | 文件头损坏 | 同上 |
| `YPF file table is truncated.` | 文件表读不全，文件不完整 | 重新获取原文件 |
| `Could not parse YPF file table.` | 布局探测全部失败，可能是本工具没见过的变体 | 把「查看信息」的输出发给开发者 |
| `找不到 ypf_archive.py` | 这个文件不在程序目录下 | 把它放回程序所在目录 |

下面两种**不是错误**，详情里会如实说明并继续处理其他文件：

- `不是归档，是 XXX 视频` —— 片头动画之类，会按真实格式原样导出。
- `空的更新槽，里面没有文件` —— 游戏预留但没用的 `update*.ypf`。

解包时如果勾了「校验文件哈希」而某个文件校验不过，会在详情里列出该文件名——
通常说明归档本身有损坏，或者路径编码选错了（试试 `gbk`、`cp949`）。

### 脚本文件本身的问题

| 报错 | 意思 |
|---|---|
| `not a script: YSCM (command table)` / `YSCF (engine config)` | 这个文件不是剧本，正常跳过 |
| `unexpected magic` / `unsupported version` | 不是本工具支持的脚本格式 |
| `section lengths do not add up to the file size` | 文件损坏或不完整 |
| `cannot decrypt with key 0x...` | 加密方式和预期不同，可能是别的游戏版本 |
| `command table ysc.ybn not found next to ...` | 脚本目录里缺 `ysc.ybn`，把它和脚本放在一起 |
| `file too small` | 文件被截断了 |
| `argc sum ... != argument count` | 文件损坏 |
| `no .ybn files found under ...` | 选错目录了 |
| `no texts/ or asm/ directory under ...` | 还没导出文本 |
| `nothing to do: enable texts or asm` | 两个输出选项都没勾 |

如果界面提示「这个游戏暂不支持回封」，说明自检没通过：工具无法保证装回去不出错，因此不让继续。
这种情况请把 `reports/` 目录发给开发者。

## 已知限制

- **只支持改文本，不支持改游戏逻辑。** ASM 清单里可以改字符串，但改指令、增删代码行会被拒绝——
  跳转和分支结构的理解程度不足以保证改完还能正常运行。
- **分段存储的台词，`
` 数量不能变。** 只影响少数台词，报错会明确指出；其余台词可自由增删换行。
- **音效名、资源名不可翻译**（标了 `frozen=1`）。改了游戏会找不到文件。
- **`ysc.ybn`、`yscfg.ybn` 不是剧本**，会被跳过，这是正常的。
- **`sjis_ext.bin` 不做处理。** 它和字符扩展的关系没有搞清楚。
- **少数原始字节的含义未确认**（如 `{{81:01}}`，全语料约 85 次），只保证原样保留。
- **只在上面提到的一部作品上验证过。** 同引擎的其他游戏可能有本工具没见过的结构，遇到时会明确报错
  而不是猜。

解包封包部分：

- **封包结果不是逐字节复原**，只保证解包出来的内容一致（见上文）。原始归档请自行备份。
- **原归档里内容相同的文件会共用一份数据，封包时不做这个优化**，所以重新打包后体积可能变大。
  实测一个 11 个相同文件的小归档从 590 字节变成 1310 字节；内容不同的归档体积不变。
- **`.ypf_meta.json` 不能删**，否则封包时文件类型和压缩方式只能靠扩展名推断，可能和原版不一致。
- **已实测版本 290 / 292 / 500 共 6 种布局**（见开头的验证范围）。更老或更新的版本工具会自动探测
  布局，但没有实测数据；探测失败会明确报错而不是产出错误结果。
- **归档里的脚本可能是本工具没验证过的版本。** 目前支持 YSTB v300 和 v553；遇到别的版本
  （如 v500）会跳过并报出版本号，不会猜着处理。想支持新版本需要先按同样的方式逐项实测。
- **命令表（`ysc.ybn`）必须能找到。** 有些游戏把它放在归档里（如 `pac/bn/ysbin/ysc.ybn`）而不是
  脚本旁边，这种情况先解包该归档，工具会自动往上层找。找不到会明确报错。
